# PJSK 游戏数据上传模块（服务 0.4.0）

Rust Bot 仅负责 QQ 交互，通过认证的本机 HTTP 调用 Go 服务；沿用现有消息框架和模块 Map。Go 源码单独交付，本仓库不存储 HAR、设备运行配置或游戏凭证。

## 配置与升级

在同一 Linux 主机启动 Go 服务，默认 `127.0.0.1:8080`。复制 `pjsk_upload.example.json` 为 `pjsk_upload.json`，配置 enabled、Bot QQ、开放群及共享 API key 文件路径；也可使用 PJSK_BOT_CONFIG 指定路径。Go 与 Bot 的开放群必须一致。真实配置和 key 不提交仓库。

Bot 与 Go 必须配套升级至本版本。保留 config.json、api.key、data 目录及 master.key，禁止重新初始化旧目录。Go 原 profile_file 保留；TapTap 另设置 taptap_profile_file，指向私下交付的 taptap-runtime-profile.json。SQLite 新字段自动兼容旧快照；旧昵称显示“暂未获取”，首次成功更新或重新授权后补全。旧用户在第一次绑定或更新前需同意当前条款。

## 帮助与用户路径

唯一帮助入口：`/help` → `/help PJSK数据上传` → `/help PJSK数据上传-绑定账号`。

使用既有 FnHandler.help / sub_help；支持多个子项和 `-all`。白名单外群聊隐藏本模块、子功能及详情。

1. 在开放群发送 `申请绑定`。
2. 私聊或群临时会话发送 `绑定账号 手机号` 或 `绑定账号 TapTap`（英文大小写不敏感）。
3. 首次操作阅读完整条款，发送 `同意条款`，自动继续本次操作。条款实质更新后再次确认。
4. 手机号直接回复六位验证码；TapTap 依次打开登录和授权链接，使用同一个手机 QQ 内置网页窗口，无需安装 QQ浏览器软件。网页可能持续加载，收到 Bot 绑定成功即可关闭。
5. 绑定成功会显示编号、真实游戏昵称、UID 和登录方式；绑定会读取 Suite 核对资料，但不上传。之后手动发送 `更新数据`。

其他指令：

- `账号列表`：每个账号按编号、昵称、UID、登录方式、备注分行显示。
- `更新数据`、`更新数据 2`、`更新数据 全部`。
- `默认账号 2`、`账号备注 2 日常使用`；不填备注内容可清空。
- `重新授权 2 手机号` 或 `重新授权 2 TapTap`。必须仍是原 UID；读取昵称失败也不会覆盖旧凭证。
- `终止当前绑定`：终止当前登录、重新授权或待同意流程，不影响已有账号。
- `解除绑定 2`：核对昵称/UID，60 秒内发送 `确认解除绑定 2`。确认包含账号版本，重新授权后旧确认失效。
- `更新状态`：最近操作结果；`重传数据`：仅重传失败项的24小时缓存。

旧“上传帮助”“删除账号”“确认删除账号”“取消绑定”不再提供。每 QQ 默认最多五个账号，稳定编号不重排；移除默认账号后剩余最早账号成为默认。只操作本人的账号范围。

## 消息生命周期与持久化

短信与条款确认跨消息，模块 Map 以 (BotQQ,UserQQ) 关联操作。待同意意图最多保留10分钟，含本次手机号或渠道，仅存在内存；Bot 重启后重新发起。Go 加密保存同意版本、时间及具体授权状态。验证码不写入 Go 数据库；原 Bot 原始消息日志仍可能记录手机号和验证码。

TapTap 发送链接后，在当前消息 process 内继续轮询，最终回复后返回；不会改为脱离消息的后台 QQ 推送。超过60秒仅提示一次并继续等结果。群临时会话按 message_type=private 处理，发送保留来源群号；实际 NapCat 发送权限仍需实机验收。

绑定只有在认证、Suite 身份核对和游戏昵称读取全部成功后才提交账号。绑定读取的 Suite 不留作重传缓存、不上传。新绑定失败不保存账号，重新授权失败保留旧凭证。普通更新同时刷新昵称；账号备注不冒充昵称。

## HTTP 与边界

独立 HTTP client 不携带 NapCat Token，仅允许 loopback HTTP，并携带 Bearer API key 及 X-Bot-ID、X-User-ID、X-Group-ID、X-Scene、X-Message-ID。临时会话保留群号但 Scene 为 private。

新增 GET /v1/terms、POST /v1/consents（version）；Go 在授权、验证码校验、轮询授权及取数上传前强制检查当前条款。未同意仍可查看和解除绑定。GET accounts 新增 nickname、revision；DELETE accounts/{id} 必须携带确认时的 If-Match revision。任务项携带游戏资料，不含凭证。完整 OpenAPI 随 Go 源码交付。

本工具使用研究设备上下文，尚未实现任意全新 SDK 设备的独立初始化。GP 环境参数可能随版本和风控失效，凭证也可能过期；不自动发送短信或重试未知结果的上传。B 服尚未实现。解除绑定不删除游戏账号、已上传公共数据，也不保证撤销上游全部会话。

## 验证

Rust 原项目测试使用临时本地 PostgreSQL，不连接生产库。覆盖帮助层级与隐藏、大小写和格式、账号排版、条款跨消息/过期/终止、解除绑定版本和 TapTap 同消息轮询。Go 全量测试、race、vet 覆盖条款隔离、昵称失败原子性、迟到结果、加密存储及上传边界；已用此前真实 Suite 离线验证昵称解析。本轮没有发送短信、上传数据或改动远程服务器。
