# PJSK 游戏数据上传模块

Rust Bot 仅负责 QQ 交互，通过认证的本机 HTTP 调用独立 Go 服务。未引入新的消息调度框架，不更改原模块日志、数据库和生命周期。Go 服务单独交付，不在这个仓库中存放 HAR、平台 Token 或游戏凭证。

## 启用

1. 在同一 Linux 主机运行 Go PJSK 服务，默认地址 `127.0.0.1:8080`。
2. 将 `pjsk_upload.example.json` 复制为 `pjsk_upload.json`，设置 Bot QQ、开放群、共享 API key 文件路径，最后将 `enabled` 改为 true。也可用 `PJSK_BOT_CONFIG` 指定配置路径。文件路径不会包含实际 key 值。
3. Go 服务需要设置相同开放群。API key 只给两个进程读取，不提交实际配置或 key。

功能默认关闭。服务的 SDK 设备环境由独立程序的私有配置提供，每个用户的账号授权分别通过短信获得，不把游戏账号凭证放到 Rust 配置中。

## 指令

- 开放群 `申请绑定`：取得使用资格，离群不自动取消资格。
- 私聊 `绑定账号 手机号`，再直接发送六位验证码；跨消息状态保存在模块自身 Map，Go 保存加密的具体授权进度。
- **绑定只保存授权，不更新或上传数据。** 成功回复会提示使用 `更新数据`。
- `更新数据`：默认账号；`更新数据 2`：指定账号；`更新数据 全部`：批量。
- `账号列表`、`默认账号 2`、`账号备注 2 备注`。
- 私聊 `重新授权 2 手机号`、`取消绑定`。
- `删除账号 2` 后，60秒内发送 `确认删除账号 2`。只删除本地授权，不删除游戏账号或公共网站数据。
- `更新状态`：查看最新任务。`重传数据`：只重传24小时内缓存，不重新取数。
- `上传帮助`：完整说明。

每 QQ 默认最多五个账号；稳定编号不因删除重排。资格和账号范围由 Go 服务再次校验。原 Bot 全局黑白名单仍先于本模块生效。

## 帮助和并发行为

白名单外群聊的功能命令静默忽略；总 `/help` 不显示模块，指定 `/help PJSK数据上传` 也不显示名称或说明。白名单内正常显示。新增 `help_visible(&Msg)` 默认返回 true，其他模块无需修改。

模块注册在 TTT 和 PlusOne 之前。只在有效私聊绑定状态下接管恰好六位 ASCII 数字，普通数字消息不受影响。Map 仅保存进度引用，不保存验证码。

更新在当前 `process()` 内轮询。60秒时仅发一次慢提示，然后继续等待，最终回复后才结束该消息任务；不会启用一个脱离当前消息的后台 QQ 推送任务。其他消息仍正常并发。

失败回复只包含安全说明、阶段、业务/HTTP代码、任务ID和版本，不输出网络异常原文、Cookie或Token。按项目需求保留原 Bot 原始消息日志，因此原始日志仍可能记录手机号和验证码。

## HTTP 契约

独立 HTTP client 不复用携带 NapCat Token 的 `http_get`。只允许 loopback HTTP 地址，带 `Authorization: Bearer <api key>`，并由 NapCat 消息生成 `X-Bot-ID`、`X-User-ID`、`X-Group-ID`、`X-Scene`、`X-Message-ID`。

主要接口：`/v1/access/apply`、`/v1/access/status`、`/v1/login-attempts`、`/v1/login-attempts/{id}/verify`、`/v1/accounts`、`/v1/sync-jobs`、`/v1/jobs/{id}`。完整 OpenAPI 随 Go 源码交付。

## 验证

新模块和 Help 的七项测试覆盖验证码匹配、并发代次保护、白名单帮助可见性和60秒提醒后继续等待结果。完整 Bot 编译继续使用原 SQLx 规则，需要匹配原表结构的数据库或查询缓存。测试应使用临时本地库，不连接生产库。

Go 侧已使用本人账号实测短信校验、平台换票、游戏认证、Suite获取与单独上传；QQ/NapCat实机交互尚未在远程服务器测试。本次不修改或启动远程服务器。
