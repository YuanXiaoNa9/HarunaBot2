# HarunaBot2 开发约定

本文按当前工程实现整理框架约定，并记录 PJSK 数据上传模块遵循的开发规则。它不是一次全仓库重构要求；已有其他模块暂不改造。

## 消息生命周期与路由

消息经 msg_analysis 解析、原全局黑白名单和日志，再进入已注册 FnHandler 的 status / matches / process。普通消息和 notice 各自分发。匹配到一个模块后结束查找，不能侵占其他模块的普通数字消息。

一次 process 属于当前消息，最终回复后结束。长任务可以在该次调用内等待和发送必要过程提示；不能把最终 QQ 结果改为脱离当前消息的后台推送。定期清理内存 Map 不属于业务结果推送。

跨消息流程显式暂存状态。以 Bot QQ 与用户 QQ 共同作为归属键；一个 QQ 可以有多个游戏账号，同一用户在不同 Bot 中互不混用。Map 或 Mutex 守卫不得跨网络 await；用流程代次防止旧响应覆盖新状态，设置有效期并处理终止、重复消息和重启。

## 模块与子功能

父模块只负责注册、启用条件、入口匹配和简单路由；系列功能用 FnHandler 子处理器注册，通过 sub_match_process 分发。共享状态用 Arc 持有，业务按职责分文件，不把短信、渠道登录、账号管理、任务轮询和展示塞回入口文件。

PJSK 入口为 src/msg_sys/func_msg/pjsk_upload.rs；同名目录中的 access、binding、taptap、accounts、sync、consent 负责各项交互，client、state、commands、render、error 为共用层，tests 单独保存。subfunction 注册实际业务处理器，帮助与业务使用同一份注册表。

新增子功能应同时补充注册、命令匹配、参数检查、帮助和相关行为测试。保持旧公开指令是否兼容由该次需求明确，不私自添加相近但含义不同的指令。

## 帮助

统一入口为 /help。/help 主功能 列出简介、首次使用路径及子功能；/help 主功能-子功能 提供详细格式、示例、场景和注意事项。沿用 help / sub_help，支持多个子项和 -all；不要再创建绕开框架的独立帮助列表。

白名单外群聊隐藏受限功能的入口、子功能和详情；资格由 Go 再次校验。群临时会话根据 message_type=private 判断，保留来源群号用于 NapCat 私聊发送，不能仅凭 group_id 是否为零判断公开性。

## 错误与回复

正常结果及必要过程提示使用统一消息发送接口。实际失败返回安全的 Result / anyhow::Error，由 msg_dispatch 统一记录并回复；子模块不得先手动回复同一错误，再继续向上抛出。明确要求静默的权限拒绝可以消化为 Ok，以免泄露受限功能。

错误展示按“失败步骤、原因、影响或下一步、必要诊断”组织。阶段应是用户能理解的动作，例如游戏登录、获取 Suite、上传 Sakura；原始 URL 不能代替说明。自动恢复失败时保留最初失败和恢复失败的上下文。任务级错误与账号级错误相同只展示一次；成功回复不附内部 UUID、耗时和版本。

底层网络错误先转换为受控错误，不把请求体、Cookie、Token、手机号、验证码、HTTP 库原始异常打印给用户。原工程原始消息日志策略按项目所有者要求保留，不能据此宣称全局日志已经脱敏。

消息使用纯文本、一行一项信息、空行分隔段落。账号依次显示编号、真实游戏昵称、UID、登录方式和可选备注；不把平台昵称或备注当作游戏昵称。用户可控昵称/备注处理换行、控制字符及消息转义。引导写“手机 QQ 内置网页窗口”，避免让人误以为需要下载 QQ浏览器。

## PJSK 服务与协议边界

Rust 只负责 QQ 交互，通过 loopback HTTP 调用独立 Go 服务；不在 Rust 复制协议实现、读游戏凭证或 SQLite 主密钥。Go 源码单独交付，不混入此仓库。

先绑定、后手动更新；绑定核对 Suite 的 UID 和游戏昵称，不自动上传。绑定失败不保存新授权，重新授权失败不覆盖旧凭证。解除绑定和终止当前流程含义严格区分。首次授权及条款实质更新必须先确认，Go 接口也强制校验。

每次取数先通过游戏登录响应取得当前版本，再用于 system 和 Suite。本地版本是登录初始值与持久化缓存；不能把上次 Ready=true 当作版本一直有效。响应 appVersion 是基础版本，客户端请求头可能带构建号，不混为同一字段。客户端大版本/校验参数不兼容时停止并说明，不能猜测 app-hash。

版本缓存按渠道隔离，原子写入 game-versions.json，重启保留；当前请求使用一致的版本快照。进度经 Go 任务事件传给当前消息，按 sequence 去重；HTTP 426 仅作更新竞态的一次有界恢复。上传结果未知时不自动重传，短信不自动重发，不通过限流、人机校验失败循环尝试。

## 验证与交付

按改动选择有意义的测试：消息归属、权限、跨消息状态、终止和重启、并发、错误传播、版本同步、凭证与上传边界。无需为纯排版写大量镜像测试。

Rust 编译遵循原 SQLx 检查；使用临时本地 PostgreSQL，不连接生产数据库。Go 测试、race 和 vet 在独立服务源码执行。真实账号验证须有授权，普通测试不得发送短信或上传数据。修改文件按 rustfmt/gofmt 格式化，不无关格式化全仓库。

提交只包含源码、示例配置和文档。HAR、真实配置、设备上下文、Cookie/Token、验证码、账号库、master.key、api.key 和 Suite 文件不得提交。构建包说明架构与运行库要求；升级保留生产配置、账号库与密钥，未经批准不改动或重启远程服务器。
